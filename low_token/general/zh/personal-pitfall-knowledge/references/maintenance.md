# 写入维护规则

仅在新增、修订、查重或修复索引时读取；普通查询不用读取本文件。

1. 先通过短索引检索现象/根因/组件，最多读取最相关现有卡片。相同原因和范围更新；相似现象但原因不同则新增并关联。首次高复用问题也可入库，不要求跨聊天重复。
2. 卡片为 `entries/PIT-YYYYMMDD-short-slug.md`，ID 唯一，日期按用户时区。历史 ID 已迁移，保留正文、限定条件和来源，不批量重写。
3. 按 [entry-template.md](entry-template.md) 记录事实。软件测试与硬件结果分开；方案已验证但根因推测应明示。只有改代码或“应该好了”不等于验证。实际测试/构建/用户明确成功反馈可以证明相应范围。
4. 普通知识问答不入库。未解决问题仅在用户要求时记待验证。无新信息不重复写；反例、失效方案应修订状态并保留历史条件。
5. 不保存令牌、密钥或无关个人信息。引用真实聊天标题/链接或文件，不编造任务 ID、测试结果及来源。
6. 写卡片前重读该卡片，合并并发修改。索引不是第二份详细知识，只维护以下短摘要。方向与边界必须来自卡片；保留所有状态限定词，不把局部验证概括为已完全解决。

在当前聊天 work 下准备一份 JSON 元数据（以下是结构示例，内容需要替换）：

```json
{
  "id": "PIT-20261002-example",
  "title": "简短问题标题",
  "status": "已确认方案；根因待证实",
  "keywords": ["具体错误码", "组件名", "中文症状", "English alias"],
  "direction": "一个准确的解决方法或优先排查方向",
  "scope": "环境、版本和验证边界",
  "path": "entries/PIT-20261002-example.md"
}
```

7. 卡片保存后，用 `python <skill>/scripts/pitfalls.py index --metadata <metadata.json>` 更新该记录。工具只读取短索引和目标卡片，生成哈希，用排他锁及原子替换保留其他记录；锁占用时等写入者结束再试，不擅自删锁。
8. 然后 `get --id ...` 回读并检查新内容；确认无重复 ID、无覆盖旧条目后简短报告。索引更新失败必须报告“尚未完成入库”，不能把卡片落盘当作完全成功。普通查询发现 `STALE_INDEX` 时只修复明确涉及的元数据，不自动重建整库。
9. index.jsonl 每行一条、无明细全文；关键词最多 30 项，每项 2–100 字符，标题 ≤140、状态 ≤120、方向 ≤220、边界 ≤180 字符。用具体组件/函数/错误码与简短中英文别名，减少通用词带来的误命中。
