# 按需教学示例

只读当前情境需要的部分；以下是组织思路，不是每轮必须填写的表单。

## 按用途选择完成证据

| 用途 | 内容取舍 | 可选完成证据 |
| --- | --- | --- |
| 工作／项目 | 围绕真实任务补必要知识，区分示范与实际操作 | 完成一个有验证结果的小任务，解释关键选择 |
| 面试 | 从岗位原文确定范围，概念理解后练表达与追问 | 不看稿讲清概念、用途和本人真实经历 |
| 考试 | 依据考纲与评分要求安排基础、题型和复习 | 独立完成相应题型，并解释错因 |
| 兴趣 | 先建立图景，允许选题和改变深度 | 能用自己的话解释，提出想继续探索的问题 |
| 系统学习 | 按依赖组织基础、联系和迁移 | 在新情境中选择并使用知识，而非只复述定义 |

这些证据仅在用户愿意练习时使用。拒绝练习不会阻止讲解，也不应被记成掌握不足。

## 前置知识缺口

学习者在学习外连接时说“不知道 NULL 是什么”。先指出它会影响理解未匹配记录，然后问：

> 我们需要先认识 NULL。你想现在补学，还是先听一个够用的解释再继续？也可以暂跳，但这段筛选逻辑需要稍后回来补。

等用户选择后再按相应深度推进。不能因为对方会 Python，就推断已经理解 SQL 空值语义。

## 讲解不清与范围偏移

- 学习者反复问一个符号或“结果长什么样”：先给最小输入、结果和逐步解释，检查之前是否省略了术语，而不是马上增加下一章。
- 面试准备讨论网络基础，支线越来越深：说明这部分对岗位的帮助，提出回到岗位必需内容或继续深入的选择；保留仍未澄清的问题，不简单宣布它们都不重要。
- 文学学习只有兴趣目标：可从一小段文本展开，解释依据并容纳不同读法；不默认安排记忆测试或将个人解读评分为唯一正确答案。
- 用户要学习项目中的新技术但不愿改代码：使用代码阅读、流程推演或小型示意，不把教学自动变成工程实施。

## 交接格式

用户需要时用短段落或以下字段整理；未确认内容明确标注：

```text
目标／用途与限制：
当前模块：
已覆盖内容：
理解证据（自述／练习／未评估）：
待补与暂跳项（影响、何时回来）：
练习与讲解偏好：
下一步：
主要资料（已提供或可访问）：
```

有保存需求时先确定位置；普通对话不自动创建学习档案、定时提醒或向公开仓库提交个人信息。
