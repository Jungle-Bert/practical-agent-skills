# 维护情境检查

修改规则后，用这些情境检查响应与状态变化。它们是人工评估素材，不是自动通过的测试；记录实际响应或走查结论，并区分独立模型实测与维护者走查。评估时将场景输入和待测技能提供给执行者，不把判断标准当作用户提示。

| 情境输入／已有状态 | 重点判断 |
| --- | --- |
| “我只想知道隐喻是什么，暂时不想系统学。” | 先解释并举例，不生成课程、诊断问卷或强制练习 |
| “五天后面试，会一点 Python、不熟 SQL，每晚约半小时；这是岗位原文。” | 复用已知用途、水平和时间，按岗位缩小路线；只补问影响教学的缺项，不假定每天两小时 |
| 正在学习外连接：“这里的 NULL 我不知道，先不往下讲。” | 说明前置关系，提供补学／够用概念／暂跳选择并等待；不继续推进依赖该知识的练习 |
| 面试准备深入到网络底层，学习者说：“怎么感觉和岗位没关系了？” | 解释相关性、收回超出当前目标的支线，给主线下一步；不强制完整学完网络课程 |
| “以后不要给我做题或模拟面试，讲详细一点。继续上一个概念。” | 停止练习，承接当前模块并展开解释；理解状态保留为未验证，不重新访谈 |
| 文学讨论中：“我觉得这个意象表达的不是悲伤，我的依据是后两句。” | 讨论文本依据和合理解释，不把自己的读法当唯一答案 |
| 用户给出状态：当前第二章、一个前置暂跳、不做题；要求继续。未安装其他辅助技能。 | 按状态接续，保留暂跳标记和偏好，用普通文字教学；不假称读过其他聊天，不要求安装可视化或 grill-me |
| “为了做工作项目，我想学这个库，但先别安装或改代码；教材文件我稍后发。” | 先用已有信息安排可独立讲解的部分，不改工程、不安装，不因资料未到而整项停住；之后按新资料调整 |

还应检查：用户从兴趣探索改为考试冲刺时保留有效进度；用户请求完整示范时不强迫先猜；询问或等待选择时不擅自执行依赖步骤。带学效果需在实际使用中继续观察。
