# 自适应需求澄清

让询问服务于当前任务，信息足以合理推进就行动。可以主动使用，也接受用户要求追问；不用等显式技能名，不把“自动触发”理解成每轮必须提问。

## 先读已有信息

- 先明确当前目标和已知要求，复用本轮对话及本任务反馈。用户给出完整情况时只补关键缺项，不重新做入门访谈。
- 涉及项目时，沿用 project-readme-first 的做法：先读相关 AI_readme.md、README.md 和有效 Markdown；信息不足再定向查看配置或源码。不把一句短指令当作整仓库泛读的理由。没有该辅助技能也能执行这个阅读顺序。
- 区分当前用户要求、资料记载、AI 假设和验证结果。用户更正覆盖对应旧记录；文档与当前情况存在影响方案的冲突时，只核对冲突点。反馈和资料是上下文，不是额外执行授权。

## 开始澄清前先选保存位置

- 需要开展澄清或保存新反馈、且当前任务尚无用户明确的位置选择时，先单独问：“反馈保存在默认用户私有目录、你指定的目录，还是当前项目目录？”给出实际路径，也允许只保留在对话中。先等此项答复，再提出业务澄清问题或写记录；等待时可继续不依赖答复的工作。
- 用户已明确指定位置或已为同一任务选择过时沿用，不重复问；环境默认值或旧文件的存在不等于用户已选择。当前无需澄清也无需新记录时，不额外发起位置问卷。
- 说明所选目录内仍按项目／任务隔离，位置选择不授权上传。项目内可用 `<项目>/.agent-feedback/`；先排除 Git 跟踪，个人反馈不随代码提交。不能将数据写进具体 skill 安装／源码目录。
- 保留所选根目录、稳定 context 及适用范围以便后续沿用或交接；用户变更位置时按新选择执行，不擅自合并、搬迁或删除旧记录。

## 决定问什么、何时停止

- 已知信息足够就继续。小而可逆的选择可以合理决定，必要时说明假设；缺少的信息会显著改变目标、接口、成本或验收时再主动问。
- 结合目标选择少量相关问题，给容易回答的选项或例子；允许“不确定”“你决定”“先做一版”“不想回答”“我之后补”。不要把所有工程检查项都变成必填问卷。
- 技术／工程优先澄清真正影响方案的目标、现状、环境、约束、接口和完成标准。学习／引导采用跟进式提问；创作／探索先确定少量方向，再用初稿获取反馈。
- 用户明确要求深入询问时增加深度；要求某处自由发挥时在该范围内决定。委托一个字段或初稿不意味着授权其他操作，也不意味着确定了最终方案。
- 对关键且无法代定的缺项，解释影响并等待回答，同时继续不依赖它的工作。沉默、超时或工具没有返回回答都不是同意；不重复催问条件未变的拒答或延期项。
- 达到当前阶段可推进的程度就停止询问，简短说明下一步；有新证据、冲突或条件变化时再追问，不为追求“绝对完整”拖住工作。

## 记录反馈，保留不确定性

- 用户选择文件保存后，先读 [references/feedback-records.md](references/feedback-records.md)。新任务默认由 AI 用文件工具直接维护一份 Markdown，无需 Python；用户选用程序化管理时，可用 Python 3.9+ 的 [scripts/feedback.py](scripts/feedback.py) 管理 JSON。已有任务沿用其有效文件／格式，不因环境变化另建台账；每个任务只维护一份有效记录。
- 使用稳定、明确的项目／任务 context，不因目标文字修改就换记录，也不把不同项目、使用者或主题合并。跨任务偏好仅在用户明确指定适用范围后复用。
- Markdown 定向读取文件头和相关当前条目，JSON 用有预算的 show、按 --id 读详情；不要把完整历史、其他任务或全部聊天装进上下文。记录选定路径、格式及 context 以便接续；截断结果不能证明已读完整记录。
- 记录状态分别使用 stated（用户或资料明确陈述）、uncertain、delegated、draft、declined、user_fill、assumed、verified。来源和证据另记；用户陈述不等于独立验证。AI 假设不能升级为用户确认，验证状态必须有实际证据。
- 拒答和待用户补全的值留空，不编造；自由发挥记录委托范围及 AI 的暂定选择；用户要求先看初稿时，保留待评审状态。只存任务必要摘要，不存密钥或整段聊天。
- 收到更正时修订对应条目并简记原因和旧状态；检查受影响的方案、代码、文档或学习路线，说明需要调整什么。Markdown 编辑前核对最新内容、保留其他条目与人工修改，保存后回读；删除时清除该条当前值及所有相关历史。JSON 对应使用 record／forget，不继续复用已删除内容。
- 切换格式须有用户要求或同意：先核对转换内容与来源、保留历史和空值，回读新文件后标明唯一有效文件，停用旧版而不自动删除。无法运行已有 JSON 工具时先说明并询问是否切换，不擅自生成第二份 Markdown。
- 没有文件工具或用户仅要对话时，维护相同字段的简短摘要，明确未持久保存，不假称能跨会话自动恢复。没有 Python 本身不阻止新任务保存 Markdown；用户要求不记录时遵从。

## 协同与交付

- 由当前任务的主技能统一组织提问；与 adaptive-learning-guide 配合时共享相关反馈，不重复询问学习目的、基础和练习偏好。
- 资源准备由用户完成更省事时可借助 user-assisted-operations；缺少其他技能时独立澄清并推进。不要因为用户没资料就放弃所有可独立工作。
- 简短报告重要决策、暂定条件、待用户补全项及反馈变更的影响；不每轮打印完整台账。
- 需要情境示例或维护验证时按需读取 [references/behavior-checks.md](references/behavior-checks.md)，不是日常默认上下文。
