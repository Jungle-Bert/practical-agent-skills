# 硬件连接确认

将用户确认作为设备连接信息的第一来源，避免先自行遍历端口、查找驱动或反复尝试连接。

## 确认顺序

1. 若用户已提供当前连接状态、设备型号或端口信息，直接使用，不重复询问。
2. 在首次枚举、连接或因连接失败扩大检查前，将缺失的关键信息合并成一次简短提问：仿真器或调试器是否连接电脑和目标板、目标板是否供电、相关外设是否接好，以及已知的接口或端口。只问当前任务需要的内容。
3. 用户确认未连接或未供电时，说明具体需要连接、插拔、供电或选择的设备，等待完成后再检查设备。
4. 用户确认就绪后，使用已知设备、接口或端口进行最小必要的检查。若仍失败，优先索取具体状态或错误，再根据证据扩大检查；不要盲目扫描所有端口、重装驱动或反复连接。
5. 等待连接确认期间，继续文档阅读、代码分析等不依赖设备的工作。不能把待确认状态当成已连接，也不能把假设或仿真结果说成实机验证。

## 边界

- 确认连接不代表授权烧录、擦除、复位、重启或断开设备；依据用户当前任务和已有授权判断后续动作。
- 不要中断正在运行的测试来确认连接；用户已说明状态时只记录，除非明确要求操作或存在可信的硬件损坏风险。
- 若连接信息可以从用户已经提供的日志或配置中获得，不再要求用户重复填写。

示例：

> 连接前请确认：调试器是否已接到电脑和目标板，目标板是否供电？若已知道调试器型号或串口号，请一并说明。我会继续完成不依赖设备的代码检查。
